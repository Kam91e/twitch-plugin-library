## Context

INDEX.md is auto-generated by `.opencode/scripts/rebuild-index.js`. The script scans all `.md` files under `plugins/` for YAML frontmatter, groups them by category, and generates two views: category-grouped bullet lists and a flat table.

Each plugin `.md` file already has a one-sentence description in the form of a blockquote tagline right after the H1 heading:

```markdown
# Viewer Geolocation

> See where your viewers are coming from in real-time...
```

The tagline is consistently present in all 24 plugin files. It is not currently extracted or included in INDEX.md.

## Goals / Non-Goals

**Goals:**
- Add one-sentence description to each plugin entry in the "By Category" bullet list section of INDEX.md
- Source the description from each plugin file's existing tagline (the `> ` blockquote)
- Update `rebuild-index.js` to extract and include taglines
- Keep the "All Plugins (Table)" section unchanged
- No changes needed to any plugin `.md` file — taglines already exist

**Non-Goals:**
- Adding descriptions to the table view
- Modifying plugin frontmatter (no `description` field needed)
- Changing the tagline content or format in plugin files
- Re-structuring the INDEX.md layout

## Decisions

### 1. Source: tagline (blockquote) vs. new frontmatter field

| Option | Pros | Cons |
|--------|------|------|
| **Tagline** (chosen) | Zero changes to 24 files. Single source of truth. Already well-written. | Slightly more complex parsing (strip frontmatter, find first `> `) |
| New `description:` in frontmatter | Trivially parseable by YAML parser | Duplicates tagline. Need to update all 24 files + maintain sync |

**Decision:** Extract from tagline. No frontmatter change.

### 2. Tagline extraction logic

```
function extractTagline(content) {
  // Remove YAML frontmatter
  const body = content.replace(/^---[\s\S]*?---\n*/, '');
  // Find first blockquote line
  const match = body.match(/^> (.+)$/m);
  return match ? match[1].trim() : null;
}
```

Edge cases:
- **No frontmatter** → content is the full file, same regex works
- **Multiple `>` lines** → only the first line is used (multi-line taglines were an issue in the test run — need to handle them)
- **No tagline** → return null, skip description in output
- **Empty tagline** → treat as no tagline

### 3. Multi-line tagline handling

Some taglines span multiple lines:

```
> See where your viewers are coming from in real-time — a live breakdown
of viewer countries with ranking and join/leave feed modes.
```

Currently only the first `> ` prefixed line is reliably extracted. Options:
- **Single line only** (chosen): simpler, and the first line alone is enough context for browsing
- **Multi-line join**: harder to parse (some have line breaks mid-sentence)
- **Wrap to 80 chars**: adds complexity with minimal benefit

**Decision:** Extract only the first `> ` line. If the tagline has a continuation line, it's truncated after the first line. This is acceptable for a compact index view — readers can click through for full detail.

### 4. Bullet list format

Current:
```
- **[Name](link)** (subcategory) — Price
```

New format with description:
```
- **[Name](link)** (subcategory) — Price
  Description text from tagline.
```

Two spaces of indentation is standard GFM continuation. The description is optional — if no tagline is found, the line stays as-is.

### 5. Summary message behavior

When the orchestrator reports completed work, it should include descriptions. Source options:
- **Read from INDEX.md** after regeneration (chosen) — one query, all descriptions available
- **Read from individual plugin files** — slower, many reads required

**Decision:** After `rebuild-index.js` runs and INDEX.md is regenerated with descriptions, the orchestrator can read INDEX.md to get plugin names + descriptions for summary messages.

## Risks / Trade-offs

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Tagline format varies between files | Low | Low | All 24 files follow the same `# Title` → `> ` pattern |
| Multi-line taglines lose second line | Medium | Low | First line alone provides enough context. Full text available in the plugin file. |
| Script change breaks INDEX.md generation | Low | High | Always test after change: run the script and validate output |

## Migration Plan

1. Update `rebuild-index.js` with tagline extraction function
2. Run the script to regenerate INDEX.md with descriptions
3. Run `validate-links.js` to confirm all links still resolve
4. Review regenerated INDEX.md for formatting correctness
