## ADDED Requirements

### Requirement: INDEX.md has a category-grouped view
The INDEX.md SHALL list all documented plugins grouped by Twitch category. Each category heading SHALL include the category name and a brief description. Each plugin entry under a category SHALL show the plugin name (linked to its file), subcategory, and one-sentence description.

#### Scenario: User browses by category
- **WHEN** a user opens INDEX.md
- **THEN** they see plugins organised under Twitch category headings with descriptions

### Requirement: INDEX.md has a flat table view
The INDEX.md SHALL include a table listing all plugins with columns: Plugin, Category, Subcategory, Price, Tags. The table SHALL be sortable by columns (visually indicated, even if client-side only).

#### Scenario: User scans all plugins
- **WHEN** a user wants a quick overview of all documented plugins
- **THEN** they see a flat table with key metadata for every plugin

### Requirement: INDEX.md links to every plugin file
Every plugin name in INDEX.md SHALL be a markdown link to its documentation file. Links SHALL use relative paths.

#### Scenario: Navigation works
- **WHEN** a user clicks a plugin name in INDEX.md
- **THEN** they navigate to the correct plugin documentation file

### Requirement: INDEX.md is auto-generated from frontmatter
The INDEX.md SHALL be generated by scanning frontmatter of all files under `plugins/`. It SHALL NOT require manual updates when plugins are added or removed.

#### Scenario: Rebuild after plugin addition
- **WHEN** a new plugin documentation file is created with frontmatter
- **THEN** running the index-updater regenerates INDEX.md to include the new plugin
